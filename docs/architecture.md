# Architecture

Internal codename: Project Orbit. Default product name: KeepX.

## What exists

| Package | Role |
| --- | --- |
| `apps/web` | Next.js App Router interface, marketing pages, and download pages |
| `apps/desktop` | Electron shell that opens the local web app |
| `apps/mobile` | Expo Android app for Inbox, add, and complete |
| `apps/api` | Express REST API, MongoDB persistence, session auth |
| `packages/shared` | Domain types, recurrence, date labels, download catalog |
| `packages/validation` | Zod schemas for API input |
| `packages/api-client` | Typed browser/client for `/api/v1` |
| `packages/ui` | Buttons, inputs, dialogs, badges, theme tokens |
| `packages/config` | Shared TypeScript and ESLint configuration |
| `docs` | Design, API, security, and operations notes |

The Windows shell is `apps/desktop`. The Android app is `apps/mobile`. Browser packages are `apps/extension`. The Gmail project is `apps/gmail-addon`. macOS and iOS still have no install file. See `docs/platform-builds.md`.

## Request path

The browser talks only to the Next.js origin. `next.config.ts` rewrites `/api/v1/*` to the API process (`API_PROXY_URL`, default `http://127.0.0.1:4000`). The API sets an httpOnly `vela_session` cookie. Because the browser received that cookie from the web origin, later requests send it with the rewrite.

Server authorization uses the session. The client never chooses the user id for a query.

## Task model

A task row is the current open occurrence of a piece of work. When one date differs from a repeating series, `series` keeps the template and `occurrenceOriginalDueAt` tells the client which slot is open. Completing that date restores the template.

- Non-recurring completion sets `status` to `completed` and stores `completedAt`.
- Recurring completion writes an `Occurrence` row (the history) and moves `dueAt` to the next instant calculated in the task time zone.
- The series stops when the next instant would pass `until`, or when the number of acted occurrences reaches `count`.
- Skipping writes history with action `skipped` and advances the same way.
- Deleting soft-deletes the series. Restoring clears `deletedAt`.
- Uncomplete rolls back the latest occurrence when one exists, or reopens a non-recurring task.

Weekly rules with `byWeekday` stay aligned to the anchor week. Daily, monthly, and yearly rules advance from the current due instant. Monthly and yearly dates keep the anchor day and clamp to the month length.

## Reminders

A reminder is a MongoDB document with `fireAt` and status `scheduled`, `delivered`, or `cancelled`. Saving a task cancels its previous scheduled reminder and writes a new one. The web client polls `/reminders/pending` and shows Snooze and Dismiss on the notice. Choosing an action clears that notice. Undo notices stay up to ten seconds. Undo can restore a snooze or put a dismissed reminder back to scheduled. That is in-app delivery while a signed-in client is open. The Windows or Linux desktop shell can also raise a system notification when the OS supports it. If the account turns on email reminders and SMTP is configured, the API process sends one email for a reminder that became due within the last 15 minutes. If the account turns on push reminders, the same window applies. Browser push uses VAPID keys when they are set. Phone push uses the Expo push service only when `EXPO_ACCESS_TOKEN` is set and a device has registered. The current Android package does not register a token. Every account starts on the Personal plan. The plan changes only after a signed Stripe notice, and only when Stripe keys are configured.

## Offline behavior

The web client queues task creates, edits, completes, reopens, deletes, restores, and postpones in IndexedDB when the device is offline or the request fails. Undo can drop a queued create before it syncs. The header shows synced, pending, retrying, or needs attention. Clicking that status retries the queue when online. A same-field conflict names the fields and asks the person to keep their edit or the server edit. A change that fails after several tries uses the same Keep mine or Keep server choice. List, tag, reorder, and archive changes still need a connection. See `docs/sync-design.md`.

## Export

Passwords, sessions, access tokens, and push subscriptions are not. Existing tasks stay. Sharing is not restored, and the plan does not change. `DELETE /me` with the current password removes the account and its lists, tags, tasks, reminders, sessions, and tokens. Tasks other people added on those lists move to their Inbox. A recorded subscription blocks deletion, because this server does not cancel it. `GET /tasks?view=trash` lists deleted tasks the account can see. `POST /tasks/:id/restore` restores one of those tasks and brings back subtasks that are still in Trash. `POST /tasks/restore` does that for a selection. A task that is already open stays as it is. `POST /tasks/:id/purge` soft-purges one of those tasks when the account added it so Undo can put it back in Trash for five minutes. The response lists those purged tasks and any subtask left in Trash because someone else added it. `POST /tasks/purge` does that for a selection. `POST /tasks/purge/restore` clears `purgedAt` on those ids. `packages/shared/src/brand.ts` and `packages/shared/src/downloads.ts` are the source for the public name defaults and platform availability. Unavailable platforms have no download URL.
